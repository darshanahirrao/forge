# Public alpha launch

## Positioning

Keep the work. Change the harness.

Forge is a local workspace for developers who already use native agent tools. Keep a canonical goal, selected context, approvals, usage evidence and checkpoints across compatible tool changes. Hermes is a first-class integration and stays replaceable.

## Show this first

Demonstrate a single task rather than every settings panel:

1. Show the saved work goal, selected profile/memory and the first native artifact.
2. Settle the native attempt and create the reviewed Work Capsule.
3. Choose another compatible harness/account and review what carries forward.
4. Continue the same work and inspect the artifact through the destination's native tool.
5. Show retained approvals and separate usage scopes. Review the public receipt before copying it.

Use the repeatable native handoff conformance for technical evidence. The built-in Codex-to-Hermes example is fictional and remains labeled in the UI and exported receipt. Do not present it as a recording of a real native run.

## Announcement draft

I use several coding agents. The work should survive changing tools.

Forge keeps a local work record, selected memory, approvals, resources and token/cost evidence together while native harnesses do the execution. It connects evaluated Codex, Claude API, OpenCode, Hermes and OpenClaw routes, with a typed extension SDK for others.

The public alpha is open source. Try the isolated handoff example without a model account, or connect your own native tools. Review a public receipt without including your prompts, memory, paths or account identifiers.

Start here: https://github.com/darshanahirrao/forge

This is an early alpha for macOS/Linux. Native compatibility and account rules apply. Hidden native state is not universally portable; costs are estimates. Feedback on the first useful session and real compatibility issues is especially useful.

## Release bar

Before an announcement: verify exact public tag/main CI, both release assets and checksum, a clean archive install with production dependencies, workspace restart retention, served web assets, read-only doctor, demo isolation, receipt canaries and both-theme/phone accessibility. Keep native/live acceptance findings and the full original scope in the completion audit.

Public availability and a compelling demo make the product easier to evaluate and share. Adoption and virality require user feedback; they are not test results or guaranteed release outcomes.
