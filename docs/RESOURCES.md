# Work and native process ownership

Forge links a managed attempt to the actual native process created by its adapter. The Resources view shows the work, harness, recorded root PID, observed process tree, memory and a route back to the work's existing controls. Codex, Claude Agent SDK, OpenCode, Hermes ACP and OpenClaw Gateway use the same ownership contract. Existing foreign chats and applications remain observations.

## Evidence and lifecycle

The adapter reports its supervised child PID before releasing model input. The execution coordinator first saves that spawn report in the canonical run. On macOS/Linux it then checks the native OS parent, user and process start marker. A changed parent/user rejects registration before task input. Native worker identity and the original harness stay in SQLite with the run; startup recovery preserves the record and marks an unfinished attempt unconfirmed. Recovery does not adopt the worker or restore an old approval connection.

The native OS `ps` interface supplies PID, parent PID, UID, start marker, RSS, CPU and executable name, using a controlled C locale and UTC. Command arguments and environment values are not collected. Full process observations stay in service memory; the general process table exposes only the largest thirty processes and omits unrelated users' start/UID markers. The owned-work view can include a small worker outside that top-thirty table.

A recorded root must match the sampled OS user and start marker before its memory is attributed. A sampled descendant tree stops at another recorded root and at the current Forge service. This avoids charging a nested managed worker to two work rows. Process reparenting, detached tools, shared services and external effects remain outside this tree guarantee. RSS can include shared pages; it is not physical memory ownership or additive unique memory.

## Observations do not authorize actions

PIDs are recyclable. The start marker is an observational correlation value with the native `ps` granularity, not a cryptographic process identity. Missing, changed, duplicate or unavailable observations produce explicit unknown states. They never confirm a native exit, release capacity, replay an action, restore approval authority or authorize a signal.

The resource view links to the work panel. A current managed attempt is stopped through its existing native driver and supervised child handle. There is no API accepting an arbitrary PID to kill. After restart, a live or missing old worker remains unconfirmed. Supported attempts can use [signed original-child evidence and explicit reconciliation](NATIVE_RECOVERY.md); the process sample cannot release that hold. The Claude adapter also refuses an unexpected replacement root from a single SDK query instead of silently moving its process ownership record.

Samples are collected on demand, coalesced and cached for five seconds. A newly recorded process can initially be absent from the latest sample. This is not a continuous resource meter, hard memory/CPU cap, OS memory-pressure signal, or complete resource-cleanup interface. Quiet mode and serialized native admission still gate new managed work, account probes and inventory reads. The [opt-in macOS user service](BACKGROUND_SERVICE.md) supplies background availability separately. Other native service backends and full recovery/cleanup controls remain delivery gates.

## Resource map, v0.26

The Resources view now partitions the full OS-visible sample into the Forge host and its observed helpers, individually recorded managed attempts, recognizable native application trees, and Other. Every visible PID belongs to one group. The host stops at recorded managed roots, including unresolved roots, so a recycled or unconfirmed worker cannot inflate reported host overhead. A nested managed attempt keeps its own boundary. Conflicting receipts for the same root produce an ambiguous measurement rather than duplicate attribution. Completed, exit-confirmed historical roots no longer split a current tree.

Native app groups match exact executable basenames for the current OS user, then follow observed ancestry with boundaries at other recognized apps. They are name-matched candidates, not authenticated accounts or newly controlled processes. Generic Node/Python/Electron processes, detached tools and shared services remain Other unless an observed tree explains them. A browser embedded in Codex cannot automatically be attributed to Forge. All-user OS-visible processes can still contribute to Other. Process permissions and sampling races limit coverage; this is not an exhaustive list of hidden services or physical-memory ownership.

The machine, managed-worker rows and `forge.resource-observation/1` resource groups use one cached process sample and the same timestamp. Concurrent reads share the native query. Finished, exit-confirmed run history stays in SQLite; only current and unconfirmed worker records are materialized for resource attribution. Missing legacy exit evidence remains eligible. A failed or duplicate table is unavailable; unknown measurements remain null. The largest thirty memory consumers and the thirty busiest CPU consumers are ranked independently, so a small busy process remains discoverable. Sorting changes both the overview and detailed list. Native process CPU is the platform's `ps` scale and may exceed 100%; the whole-machine CPU metric is normalized across cores. Summed RSS may count shared pages repeatedly.

The phone layout keeps group name, process count, memory and CPU together without horizontal scrolling. Managed rows open existing work controls. Name-matched apps retain native controls; no arbitrary-PID action is introduced. Coverage and private JSON download use progressive disclosure. The download contains group IDs, root PIDs and resource measurements, not work titles, credentials, arguments, environment values or a full process inventory. Keep it private. No resource history, observer daemon or additional agent loop is created. Demo retains live machine totals without exposing local managed group identities.

## Native companion controls, v0.30.1

[Owned native Hermes/OpenClaw gateways](COMPANION_RUNTIME.md) use distinct companion resource groups in the same OS sample and boundary set. Each group shows its configured runtime name and opens that exact runtime’s existing controls. Focus moves to the named card so keyboard users can reach Stop gateway immediately; browser back returns to Resources. Observation-only, identity-changed or missing measurements never turn into process-control authority. Stop and reconciliation continue to use the original handle or exact native close evidence. The interface remains usable in both themes on desktop and phone, including when a new root is absent from the cached sample.

## Reproducible host and browser trace

After building, run `npm run test:native:resources` on macOS or Linux with Playwright's browser installed. Local runs reuse installed Chrome; CI uses its installed Playwright Chromium. The script starts only its own compiled Forge CLI with an empty temporary workspace and an owned headless browser. It records three blank-browser control samples, then six samples on Resources with normal UI polling, 5.1 seconds apart within each phase. Native child UID/start markers and disjoint observed process trees identify the host and browser. All startup measurements are retained. The report includes versions, OS/cores/RAM, elapsed times, RSS and native-reported CPU; unrelated local process names and paths are excluded. Native handles close both fixtures before their temporary directory is removed. No provider account, model call, personal job or startup service is involved.

This is a repeatable idle observation and correctness check. It does not isolate all browser startup effects, measure unique physical pages, normalize `ps` CPU across platforms, prove lower resource use than another product, or cover an arbitrary busy workflow. The six-run native handoff separately verifies that all five actual harness adapters partition the same worker measurements while preserving work, memory and artifacts. Signed native-close reconciliation is documented separately. Whole-stack busy/load benchmarks, unsupported orphan recovery, other OS pressure/service support and hard resource limits remain in the completion audit.

## Memory pressure admission

The default policy pauses new managed launches when macOS reports warning or critical memory pressure. Resources shows the report and an explicit observe-only choice. The launch dialog explains a current hold and links back to Resources. A held launch creates no run, native driver or task input. It is not queued for automatic retry. Existing managed work and foreign sessions keep their own native controls; no process is killed from this report.

The coordinator reserves preparation capacity before asynchronous memory/context reads. It queries pressure again after that preparation, reads the current resource policy, then rechecks quiet mode and work revision before native factory construction. Account checks and other managed launches remain excluded during this admission read. Changing the policy while a query is pending takes effect before construction. The generic setup export includes the policy. The optional setting defaults to protect when absent; resource observations add no persisted schema; state 7 separately protects native recovery semantics.

The evaluated macOS reader invokes only `/usr/sbin/sysctl -n kern.memorystatus_vm_pressure_level`, with a one-second timeout, small output bound and narrow environment. This masked Apple kernel interface is an optional native ABI, not a stable public cross-platform API. Its userspace Dispatch flags are 1 normal, 2 warning and 4 critical. They differ from the internal kernel enum. See Apple's [conversion and read-only sysctl implementation](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_memorystatus_notify.c) and [userspace flag declarations](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/event_private.h). Darwin 27 was checked locally. No pressure-generation command or kernel setting write is used.

Unsupported platforms, missing/denied/timed-out queries and unexpected values remain explicitly unknown. This policy acts only on a recognized elevated report; unknown coverage does not block launch and is never labeled healthy. Quiet mode remains available. Observe-only leaves reporting enabled while allowing new managed work. Neither mode reserves physical memory or enforces CPU/RSS limits. Pressure can change after admission. There is no continuous background watchdog or automatic in-flight interruption.

`npm run test:native:pressure` checks the real macOS signal and loopback admission boundary with an inert driver. The evaluated host reported warning (native flag 2); launch was held with zero native factories, workers, model calls or injected pressure. This is native OS-query/admission evidence, not a real model task or proof against an eventual out-of-memory event. Other conformance fixtures explicitly inject unavailable pressure coverage so their protocol behavior is independent of the test host; their native process ownership/tool evidence remains a separate contract.

## Validation

Functional checks cover actual child capture, retained recovery identity, PID reuse, changed users, absent roots, unknown/duplicate observations, nested worker boundaries and non-disclosure of unrelated identity fields. The six-worker native handoff check requires live OS-checked resource attribution for Codex, two Claude API profiles, OpenCode, Hermes and OpenClaw before its exact native approvals. Native tools still produce the six verified artifacts; inference stays on deterministic loopback fixtures with synthetic credentials.

Browser coverage opens owning work directly from Resources, reviews the original exact native request and continues the existing verified handoff. Desktop/mobile rendering, keyboard scrolling, overflow and axe checks use the same view. These checks prove that boundary on the tested installation; full-stack overhead, hard resource enforcement, platform coverage and external-effect fencing still require their own evidence.
