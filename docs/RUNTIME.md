# Forge v0.7.0

Implementation checkpoint, 17 October 2026. Hermes ACP now joins Codex, Claude API and OpenCode v2 in the shared execution coordinator, with real native tools, selected-memory continuity and profile handoff. The full Persistent Agency architecture remains a delivery plan rather than a claim of completed interoperability.

## Start and develop

Node.js 24 or newer is required. Run `npm ci`, `npm run build`, and `npm start`, then open `http://127.0.0.1:4710`. The built application uses one Node service. It requires no model key, cloud database, or permanently running companion runtime to open the workspace.

For development, `npm run dev` starts a watched TypeScript service on port 4710 and Vite on port 5173. Stop an existing production service before using the same API port. Run only one Forge service per state directory. Native SQLite exclusive ownership prevents a second service from modifying or recovering an active workspace.

`node bin/forge.mjs --help` describes the local CLI. `--port` and `--data-dir` override the default port and private-state directory. The equivalent environment variables are `FORGE_PORT` and `FORGE_DATA_DIR`.

## Native execution flow

Create a work record with a goal, supported native account slot, and absolute project directory. The launch dialog explains project access and asks whether metered API/external-provider use or additional credits are allowed. That choice does not purchase credits or replace provider policy.

For Codex, Forge checks the effective account through the same connection that will run the task. It requests the native `untrusted` approval policy, user review, and a workspace-write sandbox. If the server does not confirm the policy and sandbox, no turn is requested. Goals, context, acceptance criteria, user checkpoints and the profile’s applicable reviewed native memory become the native input. Continued turns use the existing session reference.

Claude managed turns require an API slot, a named environment variable containing its API key, and explicit metered permission. The official SDK runs native tools with manual permission mode, native settings and project instructions. Its native initialization must confirm API-key authentication and the requested mode. Native rules may resolve permissions before the callback. Subscription OAuth is not offered through this SDK. See [native driver setup](NATIVE_DRIVERS.md).

OpenCode uses its official v2 client and native server with an explicit profile root, configured agent/model, ephemeral authenticated loopback connection, read-only recovery guard and temporary session review policy. Its native provider identity/allowance remain unknown. Stream loss stops the attempt; native input promotion and final settlement are checked. [OpenCode setup and recovery](OPENCODE.md) explain native ownership and limitations.

Hermes uses the installed 0.17.0 ACP runtime and official framing SDK. Native tools, skills, memory, provider configuration and history remain in an explicit native home. Session provenance and default edit review are checked before input. One-time native options have a maximum 55-second inbox deadline. A process-local native outcome reporter distinguishes provider failures from ACP end-turn responses. [Hermes setup and evidence](HERMES.md) describe the private ABI contract, memory caching and unknown cost.

Native requests are associated with their exact native request ID, session, turn, work generation, and a digest. The payload digest is checked again immediately before delivery. Allow once sends only the one-time native decision. Decisions are recorded before delivery; a transport failure makes the outcome uncertain and does not cause replay. Native withdrawal and completion invalidate outstanding requests. Approval timeouts decline still-pending requests after ten minutes.

A process shutdown or lost connection marks unfinished work interrupted. Starting again requires an explicit review of native activity, detached tools, and external effects. Closing a connection is not proof that every external action stopped. Explicit verified handoff is available for Codex, Claude API and eligible OpenCode profile slots. It requires a durable source-exit receipt and rechecks the selected artifact state. Arbitrary foreign processes and external effects are not fenced by this local controller; review them at the checkpoint. Automatic quota fallback remains disabled. See [continuity details](CONTINUITY.md).

Profile/memory preparation owns the admission slot before asynchronous source reads. Current work/profile revisions and selected context are checked before driver creation. A changed selected-memory digest starts a fresh native session and omits earlier assistant excerpts with incompatible digests; the same work and earlier native history remain saved. A profile’s companion selection is a native reference, not a new managed runtime.

## Private state and local access

Defaults are `~/Library/Application Support/Forge` on macOS, the user data directory on Linux, and LocalAppData on Windows. The directory is created privately where supported and the SQLite file uses mode 0600. Work context, profile instructions, native memory/source references, aliases, native identity metadata, quota observations, usage, and receipts belong to this private database. Memory text is not copied into the source registry or prepared receipt; native harness input/history can retain delivered excerpts under native controls. Native credentials are not imported. The database is not encrypted by Forge.

The service binds only to `127.0.0.1`. Host/origin checks, a per-start CSRF token, JSON mutations, and a restrictive content-security policy protect browser access. This is a trusted local-machine application, not a remotely authenticated multi-user server. LAN hosting and phone access require a separate authenticated transport and are not enabled.

The demo uses a different in-memory database. Its accounts, work, costs, and approvals are fictional. All native execution, identity probes, usage reads, and runtime connections are blocked in demo mode. OS telemetry remains live and is labeled accordingly.

Native source references and cached titles/summaries/schedule metadata also belong to private state. Full native transcripts, schedule instructions and delivery destinations are omitted from their projection. Forgetting a source deletes its cached observation without changing native data. Different sources may describe the same session; metadata counts are not deduplicated global execution counts.

Stop Forge before making a filesystem backup of the state directory. Preserve the database and any remaining SQLite sidecar files together. The repository and setup-blueprint export exclude private runtime state. A blueprint contains generic account roles and required harness choices, without identities, paths, credentials, or work content.

## Resource behavior

Only the selected managed attempt starts a harness process. Registering an account does not start a worker. CLI discovery checks executable presence without starting every tool. The visible UI polls every five seconds, skips background-tab polling, and reuses a coalesced OS sample. There is no perpetual sampling timer when the UI is closed.

Explicit native activity reads may briefly start a metadata connection/process for Codex or Claude; they exit after the read. Discovery itself only registers known existing profile paths. Source refresh and managed launch are mutually excluded at the HTTP boundary to avoid starting both together. Native schedule definitions are read without calling repair loaders, scheduler ticks or model tools.

Work summaries are persisted separately from full context and committed atomically with it. The overview reads summaries and bounded event metadata. A task's context and recent detailed receipts load on demand; native reasoning is not captured. Raw native assistant messages have an explicit excerpt limit and retain their native-session reference.

The earlier 75 MB / 1% core target is a design target, not a passed performance result. A preliminary local sample observed about 80 MB service RSS before final packaging. Full-stack idle CPU, native-worker overhead, memory pressure, and improvement over existing tools have not been benchmarked. Report those separately before claiming a resource advantage.

## Verification

The repository includes type checks, functional/API tests, Playwright user flows, and axe accessibility checks. Synthetic native protocol fixtures never run shell commands, call a model, or write project files. They cover request correlation, one-time decisions, stale generations, expiry, withdrawal, policy mismatch, cancellation/recovery, billing admission, usage deduplication, demo isolation, revision conflicts, atomic persistence, and lightweight projections. A synthetic Hermes server checks discovery against read-only endpoints.

The installed Claude SDK passed a real stream-json transport check against a synthetic executable worker, including permission delivery, cumulative usage and native child exit. This is SDK conformance evidence, not a real upstream model run. There are 73 functional/API/continuity/driver/inventory/memory tests and ten browser flows at this checkpoint. Type checks also cover the test and native-fixture sources.

The installed Codex CLI also passed a real initialization handshake. No account lookup, paid model turn, real command approval, account migration, or private native usage import was requested for that smoke check. Separate opt-in tests now exercise actual Codex 0.159.3 and the SDK native Claude Code 2.1.301 against local deterministic providers. Both passed native approval delivery, real tool execution, exact artifact verification, usage and process exit. The Claude test verifies that conflicting project credentials/routing cannot replace the selected host configuration. [Native conformance instructions](../tests/native/README.md) explain the isolated fixtures. The additional native handoff check now chains Codex to Claude API profile one, a second isolated Claude API profile, then OpenCode v2 and Hermes ACP. Each target receives the portable context, reads the preceding artifact and writes the next artifact with its native tools. One work/profile ID, selected memory, goal, user checkpoint and five usage scopes remain. A separate two-OpenCode-profile check verifies native artifact reads/writes and distinct selected synthetic credentials. These are synthetic model responses and selected fixture credentials; live subscription/account isolation and model quality remain unverified.

The separate opt-in existing-inventory check observed 89 Codex and 25 Claude chats, nine Codex schedule definitions and four Hermes jobs on 17 October 2026. Schedule-definition hashes remained unchanged. No model turn or native job was requested. Synthetic API fixtures verify Hermes capability negotiation and OpenClaw's fixed metadata-only tool call; they do not establish live remote execution compatibility.

## State version and rollback

This checkpoint upgrades private state to version 3 so older applications cannot silently bypass profile/memory semantics. A version-1 or version-2 file workspace receives an automatic native SQLite rollback copy named `workspace.sqlite.before-v3.UUID.sqlite` in its existing private data directory before the version changes. The copy uses private file permissions. Work and history remain in the active database. Stop Forge before restoring a copy; retain the current state separately and use a separate data directory when inspecting an older checkpoint. Never combine the old snapshot with current SQLite sidecars.

The v0.5 native three-worker handoff also verifies the same persistent profile ID and selected memory marker in every native input, with an unselected section excluded. Inference remains local and deterministic. The local version-2 to version-3 upgrade retained all four sources, 114 chat observations and 13 schedules, and its private rollback copy was verified as state version 2.
