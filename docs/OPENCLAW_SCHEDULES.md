# Native OpenClaw schedules

Forge v0.33 reads existing OpenClaw jobs and adds human-reviewed pause/resume through the public `@openclaw/gateway-client` 2026.10.4 client and Gateway protocol 4. OpenClaw retains its scheduler, job definitions, tools, permissions, billing and delivery. Forge starts no scheduler, sends no tick or model input, and keeps no idle operator connection.

## Setup and access

In Activity, choose **Add source**, select **OpenClaw schedules**, and enter the existing loopback Gateway address. Reference a `FORGE_…` environment variable containing its bootstrap token, set outside Forge before startup. Save the reference, then explicitly read the source. The initial scope is `operator.read`. If native pairing is requested, approve the displayed Forge schedules device in OpenClaw and read again. The adapter requires the evaluated server version, protocol, methods and scopes before reading any jobs.

Native `cron.update` requires `operator.admin`. Only a human on the local Forge host can choose **Scheduler access**, review that broader grant, and enable changes. Private phone reviewers can subsequently review an exact pause/resume; phone and companion credentials cannot provision administrator access. Turning controls off narrows Forge's requested scope and prevents new mutations. Revoke any existing broader native grant through OpenClaw's own device controls when appropriate.

Each source has a distinct signed device identity in a private mode-0600 `.forge-openclaw-source-<source-id>.json` beside the workspace state. SDK-issued operator tokens, when returned by the native server, stay in that file. A native shared-token connection instead retains only the reference and device keys; Forge never copies the external bootstrap value into SQLite or the private file. This mode still needs that external reference on subsequent connections. Device identity survives refresh, Forge restart and a reviewed access change.

Known grant withdrawal blocks automatic bootstrap reuse. Review scheduler access locally before reconnecting. A missing previously observed identity also needs that explicit review before replacement. Private accepted-access revisions prevent an older restored database from silently regaining an earlier grant; a local review advances beyond the private receipt. Keep the private state files and database together. Source removal deletes Forge's local identity only; upstream revocation remains an OpenClaw action.

This route currently supports the selected shared-token bootstrap or a previously issued SDK operator token. It does not import native authentication stores or certify every Gateway authentication mode. Background startup needs the named reference in its own environment. The existing account credential-reference setup does not implicitly provision this source.

## Inventory and exact controls

Inventory requests native `cron.list` with compact metadata, disabled jobs included, and a limit of 100. It saves titles, rules and reported state/next/last/outcome, excluding instructions and delivery destinations. Pagination is reported when present. A recorded running timestamp remains running even if future scheduling is paused; an enabled job is not evidence that its gateway or delivery is healthy.

**Review pause** or **Review resume** fetches the full native `cron.get` record. The two-minute review includes bounded instructions and the complete definition. Oversized execution content is refused rather than truncated. Confirm native permissions, delivery and billing before applying. Resume also checks current Forge memory-pressure admission; managed-work budgets do not govern later native schedule runs.

The `openclaw-native-revision/1` contract binds the source, endpoint, signed device, access revision, requested scopes and evaluated version. The native job's opaque `configRevision` is hashed for Forge's review and passed unchanged as `expectedConfigRevision` to `cron.update`. OpenClaw performs the final revision comparison under its native transaction. A change before submission or during the read/update gap rejects the action. The access digest is a connection-authority binding, not a hash of all Gateway configuration; global native permissions, defaults and delivery policy remain native at execution time.

A successful scheduling-state acknowledgement becomes an applied human receipt. An already matching state can be observed without another write. Correlated native `CRON_JOB_CHANGED` is a pre-effect rejection. Lost acknowledgements remain uncertain, and the same receipt never resends a mutation. Only a correlated response on the authenticated native connection can establish a native revision refusal or absent-or-hidden observation; a locally constructed error or disconnect cannot. Native `CRON_JOB_NOT_FOUND` also covers visibility restrictions, so Forge records `not-visible-or-absent` with an unknown enabled state. It never interprets that response as proof of deletion or disabled scheduling. An uncertain action holds another control and source removal until a fresh native-state read and attributed human outcome review. Controls may be disabled while that read-only review is performed. Shutdown stops finite clients, drains the admitted operation, and saves its receipt before storage closes.

Pausing future scheduling does not settle already selected jobs, running tools, detached work or delivery. This release does not create, edit, delete, trigger, translate or transfer a schedule. A safe owner transfer needs its own reviewed mapping and native quiescence evidence. See [the completion audit](COMPLETION_AUDIT.md).

## Verification and upstream interfaces

`npm run build && npm run test:native:openclaw-scheduler` uses the compiled Forge client, actual installed Gateway and native CLI in a disposable owned profile. It checks read-only access, identity continuity, administrator scope, pre-submit and native-transaction races, idempotent receipts, lost acknowledgement without replay, native absent-or-hidden review with controls disabled, unchanged native configuration and signed original-child closure. A loopback provider counts requests; the fixture must finish with zero model requests. It never points at a personal native home.

Functional/API tests cover private-file, revocation, rollback, bounded review, local/phone authority and shutdown behavior. Browser fixtures separately check setup, exact reviews, accessible fixed footers and phone actions in both themes. Synthetic UI evidence is not actual device, delivery or provider acceptance.

Primary interfaces: [public Gateway SDK](https://docs.openclaw.ai/concepts/openclaw-sdk), [Gateway clients](https://docs.openclaw.ai/gateway/clients), [operator scopes](https://docs.openclaw.ai/gateway/operator-scopes), [native cron](https://docs.openclaw.ai/automation/cron-jobs) and [job management](https://docs.openclaw.ai/automation/managing-jobs). The evaluated native 2026.10.4 implementation additionally establishes the opaque revision, compact list and transactional expected-revision behavior; these are version-pinned compatibility requirements, not assumptions about other versions.
