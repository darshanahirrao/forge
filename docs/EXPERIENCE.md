# The Forge experience

**You stay in Forge. Compatible engines change underneath.**

Persistent Agency should feel like one ongoing working relationship. The user's authored identity, preferences, projects, decisions, shared connections, policies, and history remain in the workspace. A harness is an explicit execution choice. Switching it should preserve the surrounding work and explain only differences that matter to the outcome.

## Home is ongoing work

Open Forge to three useful answers: what moved forward, what needs a decision, and what is consuming capacity or money. Lead with outcomes and factual state. A task joins native conversation/activity, plan and artifact references, evidence, and cost. Existing browser, computer-use, terminal, or editor surfaces can be opened or attached when supported; Forge does not recreate their execution capabilities.

One goal entry can capture an outcome and delegated scope. The selected runtime, initially Hermes or OpenClaw, helps clarify and plan when needed. The interface should let the user choose the companion runtime, execution harness, and model separately, or allow an explicit routing policy. Ordinary work proceeds within the granted scope. A new decision is needed when an action exceeds that scope or the native harness requires it.

## A switch that preserves the workspace

The user chooses another runtime or harness in the same workspace. Forge checks access, required capabilities, active actions, workspace changes, and a safe checkpoint. When compatible, it continues with a new native binding under the same profile and work record. The existing timeline, memory, files, policies, and accounting remain visible.

Surface an incompatibility before activation. Do not make the user rediscover a missing tool after a silent switch. Preserve native capabilities through extensions; expose what cannot be carried across. State continuity is the product promise. Identical model behavior remains an empirical question.

## Calm control

Resource view connects a process, terminal, browser context, or API request to its work and owner when known. Quiet mode prioritizes foreground capacity and queues managed background work. Cleanup previews the exact owned resources and their consequences. Unknown ownership remains visible and separate from safe cleanup.

An approval inbox shows the concrete action, relevant context, and consequence. Supported requests can be settled from a paired phone. Alerts are reserved for meaningful progress, failures, and decisions, with user-controlled delivery. Offline machines show the last observed state. An optional available worker is required for actual continued execution elsewhere.

## Memory and cost are inspectable

A remembered decision has a source, scope, and correction path. Relevant evidence appears when useful without requiring the user to reread past chats. A source is not a fresh instruction. User corrections should change subsequent retrieval across harnesses.

Every dollar view says how it knows. Tokens, caches, retries, tools, and failed attempts roll up to the task without double counting. Estimated API-equivalent cost and confirmed charges remain visibly distinct. The useful question is what an accepted outcome consumed, including the work required to recover from failures.

## The demonstration to build

Start a real artifact task with Hermes assisting and Claude Code executing. Save a verified checkpoint, switch to Codex, and continue through the same workspace. Record an approval on the phone, interrupt a worker, reconcile the action, recover, and verify the final artifact. Show the complete resource and usage record with missing coverage marked.

Compare that run with a same-harness control. Independently replace Hermes with OpenClaw and verify profile, memory, policy, and work continuity. Repeat execution with OpenCode after the first pair is reliable. The experience earns its claims through this evidence. A smooth animation cannot substitute for correct continuation.

## Keep the product light

Render the current work first. Open or attach existing native surfaces on demand, and stop unused owned resources through supported lifecycle controls. Implement the coordination and visibility gaps without replacing harness capabilities. Measure whole-stack overhead. Advanced metrics and native details remain available through progressive disclosure.

This is the proposed experience. No part of this scenario has yet been implemented in Forge.
